# Community 模块产品评审文档

> 模块定位：事件型临时社交，不是朋友圈，不是好友列表。
> 核心理念：活动结束，聊天室自动关闭，不留社交压力。
> 设计原则：弱关系、零负担、基于事件而非基于人。

## Page 18：社区首页（活动列表）

### 页面定位

展示附近即将发生或正在进行中的活动，用户可以浏览和报名。**绝对不是朋友圈feed流。**

### 核心信息架构

- 顶部：活动类型筛选条（运动/读书/电影/音乐/咖啡/其他）
- 时间筛选：今天/本周/周末
- 距离筛选
- 活动卡片流：封面图+活动名+标签+时间+地点+人数+"几缺几"+距离
- 发起活动按钮（右下角浮动）

### 状态清单

#### 1. 有活动

- 列表/卡片视图。
- 每张卡片展示：活动名称、类型标签、时间、地点、已报名人数（"2缺2"格式）、距离、封面图。

#### 2. 无活动/冷启动

- **绝不能空白**。
- 展示"附近有什么好玩的"探索引导。
- 提供来自Explore模块的地点作为"活动灵感"，提示"这些地方很适合举办小聚，要发起一个吗？"
- 可与本地合作伙伴（咖啡馆/书店/健身房）进行种子活动合作。

#### 3. 活动已满员

- 标记"已满"。
- 仍可查看详情并加入候补（若支持）。

#### 4. 活动已结束

- 不再出现在首页。
- 转入"往期"或归档（从"我的"中查看历史活动）。

### 交互细节

- 顶部筛选：活动类型、时间（今天/本周/周末）、距离。
- **报名按钮直接在卡片上**：一键报名，报名后按钮变"已报名"并提供取消选项。
- 支持分享活动到外部，吸引朋友加入。
- "几缺几"格式比"已报名X人"更有行动感（"2缺2"比"已报名2人"更有加入冲动）。

### 极端情况

| 场景 | 处理方式 |
| --- | --- |
| 报名后活动临时取消 | 通知强提醒已报名用户，提供替代活动推荐 |
| 恶劣天气导致户外活动风险 | 主动标记风险活动，建议组织者修改或取消 |
| 活动信息虚假/欺诈 | 举报入口+快速审核响应 |
| 用户所在地区活动极少 | 扩大距离范围；推荐线上活动；引导发起活动 |

### 产品逻辑断裂点（待修复）

- [ ] 当前原型需完善"几缺几"展示格式
- [ ] 缺少冷启动空态（活动灵感+引导发起）
- [ ] 缺少活动类型/时间/距离筛选
- [ ] 卡片上一键报名按钮
- [ ] 已满员状态和候补
- [ ] 浮动发起活动按钮

## Page 19：活动详情与报名

### 页面定位

活动完整信息页，包含介绍、时间地点、参与者、聊天入口。

### 核心信息架构

- 顶部：返回 + 分享
- Hero 区域：活动封面图/渐变
- 浮起信息卡：活动名+类型标签+时间+地点+"几缺几"
- 活动描述
- 集合点地图
- 参与者头像墙
- 组织者信息（轻度展示）
- 注意事项
- 底部：报名/已报名/加入聊天 按钮

### 状态清单

#### 1. 报名未开始/进行中

- 展示活动详情、组织者信息、已报名用户头像墙、活动描述、注意事项。

#### 2. 用户已报名

- 显示"你已报名"状态。
- 提供"加入活动聊天"入口（跳转Page 20）。
- 添加到日历、分享给朋友。

#### 3. 活动已满

- 显示候补入口。
- 推荐类似活动。

#### 4. 活动取消

- 页面顶部醒目提示取消。
- 推荐替代活动。

#### 5. 活动进行中

- 显示"正在进行中"标签。
- 提供聊天室快捷入口。
- 集合点导航。

### 交互细节

- **参与者列表**：头像+昵称，点击查看轻度资料（共同兴趣标签），**不能是完整个人主页**，防止社交压力。
- 活动地图：显示集合点和活动路线。
- "邀请朋友"：生成带活动信息的分享卡片。
- 报名/取消：一键操作，无需复杂表单（MVP阶段）。

### 极端情况

| 场景 | 处理方式 |
| --- | --- |
| 报名后未出席且未取消（多次） | 轻度影响信誉分，初期不做惩罚 |
| 活动涉及收费 | MVP避免；若引入需完整支付+退款流程 |
| 组织者失联 | 其他参与者可看到组织者最后活跃时间；提供退出选项 |
| 活动人数过少（1人但最低2人） | 提示"目前只有1人报名，可能会取消"，推荐备选 |

### 产品逻辑断裂点（待修复）

- [ ] 页面未创建
- [ ] "几缺几"人数展示
- [ ] 参与者头像墙（仅显示共同兴趣，不暴露完整资料）
- [ ] 活动取消醒目提示
- [ ] 一键报名/取消
- [ ] 加入聊天室入口

## Page 20：活动聊天室

### 页面定位

围绕单个活动的临时讨论空间，用于集合沟通、分享照片、更新进展。**活动结束自动删除。**

### 核心信息架构

- 顶部：返回 + 活动名 + 参与者数 + 更多操作
- 倒计时/状态提示："活动即将开始"/"正在进行"/"聊天室将在24小时后自动删除"
- 消息列表
- 照片墙聚合区（分享的照片自动聚合）
- 底部：输入框 + 发送 + 照片按钮

### 状态清单

#### 1. 活动前（预热期）

- 成员加入欢迎语。
- 组织者可以发布集合点详情。
- 成员可以提问。
- 活跃度通常较低。

#### 2. 活动进行中

- 实时位置共享（可选）。
- 照片分享。
- 即时消息。
- 这是高频使用期。

#### 3. 活动结束后 N 小时

- 聊天室进入**只读模式**。
- 顶部提示"聊天室将在24小时后自动删除"。
- 用户可以保存重要照片或消息。

#### 4. 已删除

- 用户从通知或历史记录点击进入时：
  - 显示"这个聊天室已经完成了它的使命 ✨"
  - 下方推荐同类型即将开始的活动

### 交互细节

- **照片墙**：聊天室中分享的照片自动聚合到照片墙，方便浏览和保存。
- "保存到我的相册"：单张照片一键保存，长期保留。
- 提及/回复功能：轻量，不复杂。
- **退出聊天室但不退出活动**选项：不想被消息打扰但仍参加活动。
- 不显示"已读"状态，减少社交压力。

### 极端情况

| 场景 | 处理方式 |
| --- | --- |
| 聊天室无一人发言 | 自动删除时不产生任何负担 |
| 不友善内容 | 举报入口+快速审核（初期关键词过滤） |
| 用户不想被打扰 | "退出聊天室但不退出活动"选项 |
| 有人发广告/骚扰 | 举报+组织者可移除；多次违规限制活动发起权限 |
| 活动前组织者发重要通知 | 消息特殊样式（置顶/不同颜色） |

### 产品逻辑断裂点（待修复）

- [ ] 页面未创建
- [ ] 临时聊天的生命周期设计（预热→进行中→只读→删除）
- [ ] 照片墙聚合
- [ ] 自动删除倒计时提示
- [ ] "聊天室已完成使命"空态
- [ ] 退出聊天室但不退出活动
- [ ] 举报和审核机制

## Page 21：活动结束与回顾

### 页面定位

活动结束后的轻量回顾页，承载回忆和社交连接。

### 核心信息架构

- 活动封面/合影
- 活动总结数据：参与人数、活动时长、总步数/里程（如适用）
- 一句话AI总结（"大家一起走了5公里，拍了23张照片"）
- 照片墙（所有人分享的照片）
- "和你一起参加的人"（头像+昵称，可轻量连接）
- 同类型活动推荐
- 分享按钮

### 状态清单

#### 1. 活动正常结束

- 展示活动合影（若有）、参与人数、活动时长、一句话总结。
- 照片墙展示所有分享照片。

#### 2. 用户主动退出

- 不展示此页面。

#### 3. 轻量连接（可选）

- "和你一起参加的人"展示头像。
- 提供"发送好友请求"入口，但这是弱需求，**初期可简化或省略**。
- 产品哲学：不建立好友关系，而是"我们曾一起做过一件事"的弱连接记忆。

### 交互细节

- "分享这次活动"卡片。
- "查看同类型活动"推荐入口。
- 活动数据可沉淀到Growth模块（如"参加了3次线下跑步活动"）。
- 保存照片到本地。

### 极端情况

| 场景 | 处理方式 |
| --- | --- |
| 参加了不愉快的活动 | 不强迫回顾或评价；提供"不感兴趣此类活动"反馈入口 |
| 无人分享照片 | 照片墙区域留白，不强行展示占位图 |
| 活动中途解散 | AI总结中性描述"这次活动提前结束了"，不评判 |

## 设计原则（全局）

1. **事件型社交**：基于活动而非基于人，没有好友列表，没有朋友圈。
2. **零压力**：聊天室自动消失，没有永久社交关系的负担。
3. **"几缺几"行动感**：用"2缺2"代替"已报名2人"，降低参与门槛。
4. **轻连接**：可以看到参与者的共同兴趣，但不暴露完整个人资料。
5. **组织者轻责任**：MVP阶段组织者只是"发起人"，不是"管理员"，减少组织负担。
6. **安全第一**：公开活动有举报机制，地点建议公共场所，不鼓励私人空间聚会。
7. **无社交债务**：退出聊天室但不退出活动，活动结束不用"互加好友"，不用维持关系。
