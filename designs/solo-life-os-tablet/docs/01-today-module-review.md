## Page 01：今天（首页）

### 页面定位

打开 App 的第一眼，让用户在 **3 秒内**知道今天可以怎么过。

### 核心信息架构

- 顶部：日期 + 天气 + AI 入口
- 今日状态问候（情绪问候卡片）
- **AI 今日卡片**（Killer Feature）：时间块概览（上午/下午/晚上/睡前）
- 附近推荐（2 张横排小卡）
- 今日小目标（4 个圆形进度）
- 晚间入口卡片（晚上才出现或常驻）
- 底部 6 Tab 导航

### 状态清单

#### 1. 首次使用 / 无数据

- **不应该**展示空日历或空白页。
- 提供温柔的开始：
  - 一句话问候（"早上好"）
  - 引导："今天感觉怎么样？想出门吗？"
  - **懒人入口**：根据当前位置/天气/时间自动生成一份宽松建议（"此刻附近的3个咖啡馆"）
- 核心目标：避免用户因选择空白而流失。

#### 2. 今日已有规划（当前原型覆盖）

- 清晰展示时间块（上午、下午、晚上、睡前）
- 每个块**只显示标题、地点名、时间**，加展开/进入详情按钮
- **不要直接把全部细节摊开**：上午9点看到晚上11点的详细计划，信息压力大，容易产生"今天好累"的心理暗示。

#### 3. 中途被打乱 / 已偏航

- GPS 检测到用户没有按规划行动，或时间已过某个块。
- 页面不应"僵死"。
- 顶部出现**轻量状态提示条**："下午的咖啡看起来没去？要重新规划剩余时间吗？"
- 这是连接 Page 03（重新规划）的关键入口。

#### 4. 加载失败 / 网络异常

- 必须保留**昨天的缓存规划**。
- 给出清晰的重试提示，不能白屏。
- 提示文案要口语化："网络有点慢，先看看昨天的安排吧"。

### 交互细节

- **时间块长按菜单**：提供"跳过 / 已完成 / 替换"快捷操作，减少进入详情页的次数。
- **一键导航图标**：每个地点时间块右侧应有小地图/导航图标（调起地图App），高频刚需。
- **下拉刷新**：触发"AI 重新生成今日建议"，**必须带二次确认**，防止误触丢失手动调整的规划。
- **今晚记录卡片**：根据时间动态显示，傍晚后出现，引导进入今日总结。

### 极端情况

| 场景 | 处理方式 |
| --- | --- |
| 用户关闭位置权限 | 自动回退到手动选城市/区域；弱化"附近推荐"，转化为基于时间的泛化建议（"下午适合阅读"） |
| 一天安排超过 6 个事件 | 信息密度折叠；引入"今日已排满，其他建议放入'稍后考虑'" |
| 极端天气（暴雨/高温） | 首页状态卡片自动切换，AI建议室内活动 |
| 凌晨打开（0:00-5:00） | 不展示当日规划，展示"早点休息"晚安卡片，不刺激使用 |

### 产品逻辑断裂点（待修复）

- [ ] 当前原型把全部时间块的推荐文案直接展开，需要折叠
- [ ] 缺少偏航提示条
- [ ] 缺少长按快捷操作
- [ ] 时间块缺少一键导航图标
- [ ] 首次使用空态未设计
- [ ] 网络异常态未设计
- [ ] 位置权限拒绝态未设计

## Page 02：今日规划详情

### 页面定位

展示一天从早到晚的完整时间轴安排，允许用户进行微调。

### 核心信息架构

- 顶部导航：返回 + "今日规划" + 重新规划
- 今日概览条：日期、天气、预算、幸福指数、外出次数、步数
- **时间轴**（核心）：左侧时间+圆点+竖线，右侧活动卡片
- 底部操作栏："AI帮我调整" + "开始今天"

### 状态清单

#### 1. 没有 AI 推荐理由（用户手动添加活动）

- 不应空着一块"推荐理由"区域。
- 展示用户自己的备注；若无备注则展示上下文（如"在你喜欢的上城区"）。

#### 2. 跨天规划

- 晚上 11 点的电影可能跨越到第二天凌晨。
- 时间展示需要明确日期边界（如"7/28 23:30 - 7/29 01:45"）。

#### 3. 过期事件

- 事件时间已过但用户没标记完成。
- 进入详情时状态显示"已过期"。
- 提供操作："标记已完成 / 移除 / 今天再做一次"。

### 交互细节

- **地点卡片**需包含：距离、营业时间（与当前时间对比，即将关门用红色警告）、是否营业中。
- **活动前提醒**快捷设置（提前 15 分钟提醒），无需跳出到系统设置。
- 若活动关联联系人（未来扩展），一键分享"我下午3点会在XX咖啡馆"。

### 极端情况

| 场景 | 处理方式 |
| --- | --- |
| 地点已关店/暂停营业 | 详情页顶部显著但非阻断预警，引导 AI 重新规划 |
| 活动是"阅读"等无地点任务 | 不强行要求地点，详情页简化为时间+书籍信息+感想输入框 |
| 全天事件（如"今天在家休息"） | 时间轴特殊样式，不占具体时段，显示为全天横幅 |

### 产品逻辑断裂点（待修复）

- [ ] 营业状态警告（即将关门红色提示）
- [ ] 过期事件状态和操作
- [ ] 无地点任务（阅读/冥想等）的详情页简化样式
- [ ] 活动前提醒快捷设置
- [ ] 地点关店预警条

## Page 03：AI 重新规划（关键壁垒页面）

### 页面定位

当计划被打乱时，用户表达新需求，AI 即时重构剩余时间。**这是形成竞争壁垒的页面**。

### 核心信息架构

- 顶部导航：返回 + "重新规划"
- AI 对话感开头（头像 + "今天有什么变化吗？"）
- **场景选择 chips**（多选，核心交互）
- 预算调整 slider
- 时间偏好（轻松/适中/充实）
- 底部主 CTA："AI 重新规划今天"

### 状态清单

#### 1. 需求模糊时

- 用户只说"今天不想动"。
- AI 需要一轮轻量追问，但**不是自由聊天**。
- 快速提供 3-4 个结构化选项卡片：
  - "居家观影套餐"
  - "在家做一道新菜"
  - "线上听一场 Live"
  - "窗边发发呆"
- 用户一点即选，避免对话成本。

#### 2. 预算/时间等约束改变

- 直接展示可滑动的参数调整栏（时间范围、预算 slider、出行方式）。
- 用户快速输入约束，不用自然语言敲一堆字。

#### 3. 规划生成中（等待态）

- **不能只是一个 loading 圆圈**。
- 等待文案要有温度："正在根据你的心情和天气，重新编织一个下午..."
- 动态插画/渐变动画。
- **等待容忍度与情感价值成正比**。

#### 4. 生成失败 / 无可推荐

- 必须给出明确的有用提示，不能冰冷说"无结果"。
- 示例："附近暂时没有适合的室内活动，但步行街的雨棚很漂亮，要不试试雨中漫步？"
- 永远给一个"保底建议"。

#### 5. 新规划展示后（对比视图）

- 必须提供"保留原计划 / 采用新计划"对比。
- 允许**部分替换**（只换掉下午，保留晚上）。
- 这是高级功能，MVP 可以先做全量替换，部分替换放在 2.0。

### 交互细节

- 每次重新规划，后台记录原因（天气、预算、心情），为 AI 积累数据。
- Chips 选中有触觉反馈（视觉上的 scale 动效）。
- 预算 slider 实时显示金额。

### 极端情况

| 场景 | 处理方式 |
| --- | --- |
| 用户连续多次不满意（>=3次） | 主动切换策略："要不要告诉我你具体想做什么？"引导更明确表达，避免无效循环 |
| 凌晨 2 点请求规划 | AI 知道此时大部分店铺关门，推荐夜间便利店、24h 书店、居家活动 |
| 预算极低（<30元） | 推荐免费/低成本活动：公园散步、图书馆、橱窗逛街、在家做某事 |
| 用户位置在陌生城市（旅行中） | 弱化"附近常去"逻辑，强化"游客友好""值得一去"标签 |

### 产品逻辑断裂点（待修复）

- [ ] 缺少规划生成中的等待态（当前直接跳转）
- [ ] 缺少新旧规划对比视图
- [ ] 模糊需求时的结构化追问选项未设计
- [ ] 连续不满意的策略切换
- [ ] 生成失败/无结果的保底建议态
- [ ] 凌晨/极端时段的智能适配

## Page 04：活动详情

### 页面定位

解释"为什么推荐这个活动/地点"，建立信任感。是 AI 推荐可解释性的关键页面。

### 核心信息架构

- 透明顶部导航（在 Hero 图上）：返回 + 收藏
- Hero 渐变区域（氛围图）
- 浮起信息卡片：AI 推荐标签 + 标题 + 评分 + 人均/距离/营业时间
- **为什么推荐给你**（核心差异化：AI 个性化理由）
- 适合标签（一个人/办公/拍照/安静...）
- 评价预览
- 底部操作栏：导航 + 标记已去/加入计划

### 状态清单

#### 1. 单人活动 vs 多人活动

- 单人活动（独自散步/咖啡）：强调安全指数、安静程度、"一个人不会尴尬"标签。
- 多人活动（剧本杀拼车/City Walk）：显示最低人数、当前拼车状态、已报名人数。
- 界面元素需要适配两类活动。

#### 2. 历史打卡

- 如果用户以前去过，显示"你上次来这里是在 2026 年 3 月"。
- 这是**情感钩子**，也能防止 AI 重复推荐已经厌倦的地方。

#### 3. 即将发生的临时活动

- 如"今晚 8 点草坪音乐会"。
- 倒计时显示。
- 活动已开始：立即置顶提醒"正在进行中"。

### 交互细节

- **收藏按钮**要明显，给出即时反馈（心形填充动效）。
- 收藏逻辑和 Explore 模块的收藏夹打通。
- **AI 推荐反馈**：不做长篇大众点评式评价，提供"对本次推荐的准确性"打星：
  - "这次推荐很棒"
  - "一般"
  - "不感兴趣"
- 这个反馈**直接用来训练 AI 推荐模型**，极其珍贵。
- 外链跳转（购票、预订）：做安全拦截提示，或内嵌 WebView。

### 极端情况

| 场景 | 处理方式 |
| --- | --- |
| 活动已取消/结束 | 页面更新状态，提供"反馈此活动已变更"轻量入口（群众修正） |
| 商家永久关闭 | AI 自动从推荐池移除，并在详情页顶部标注"已关闭" |
| 价格超出用户预算 | 显示实际价格，标注"超出你今天的预算 ¥XX"，但不禁止用户选择 |
| 涉及购票/预订 | 标注"需要提前预订"，提供直达链接 |

### 产品逻辑断裂点（待修复）

- [ ] 缺少"你上次来过"的历史打卡提示
- [ ] 缺少 AI 推荐准确性反馈（打星）
- [ ] 临时活动的倒计时/进行中状态
- [ ] 单人/多人活动的界面差异化
- [ ] 活动取消/关闭的状态提示
- [ ] 外链安全拦截/内嵌 WebView

## Page 05：今日总结

### 页面定位

晚间给予用户成就感和正反馈，强化明日留存。这是**情感留存**的关键页面。

### 核心信息架构

- 透明顶部导航（深色 Hero 上）：关闭 + 分享
- 深色夜色渐变 Hero：月亮 + 日期 + "今天过得怎么样？" + 幸福指数星级 + 一句话总结
- 浮起数据卡片：步数 / 外出次数 / 花费
- 完成的事（已完成打勾，未完成淡化）
- 今晚心情快速记录
- **AI 今晚的话**（温暖寄语卡片）
- "晚安，明天见"按钮

### 状态清单

#### 1. 没有任何完成项（零完成态）

- **绝对不能**显示"今天什么都没做"这种刺眼文案。
- 温暖表达："今天或许只是需要休息，也是一件重要的事"
- 展示微小积极数据：步数、天气、"今天天气不错"、一首音乐记录
- AI 寄语要温柔，不能有任何失望或激励施压的语气。

#### 2. 只完成部分

- 已完成事件打勾（绿色/主色）。
- 未完成事件淡淡划过（muted 颜色，删除线或透明度降低）。
- **允许用户手动补充完成**：比如"散步虽然没去，但给朋友打电话聊了很久"，可以手动添加这件温暖小事。

#### 3. AI 生成的总结

- **必须可编辑**。
- AI 可能说错话，用户需要能删掉或重写某一句。
- 提供"换个说法"按钮让 AI 重新生成。

### 交互细节

- **分享按钮**：生成一张美观的卡片（不出现具体地理位置以保护隐私），可分享到社交媒体。这是**重要的增长钩子**。
- **记录心情入口**：一次点击即可选择表情，不带任何步骤，极轻量。
- **明日计划预览**：如果当天完成度高，可以轻声问"明天需要为你准备什么吗？"，不是强制。
- "晚安"按钮点击后，返回首页并切换为"明天见"晚安状态。

### 极端情况

| 场景 | 处理方式 |
| --- | --- |
| 深夜 23:59 打开 | 避免生成让人兴奋的总结，提供"明天早上为你准备好"选项 |
| 涉及敏感内容（情侣私密地点） | 总结中不输出地点全名，泛化为"你们一起看了日落" |
| 用户连续多天零完成 | AI 语气更加温和，不施压，可能推荐"今天试试只做一件小事" |
| 特殊日期（生日/节日） | Hero 区域特殊装饰，AI 寄语特别定制 |

### 产品逻辑断裂点（待修复）

- [ ] 零完成态的温暖文案和展示（当前只有"完成3件事"的正面态）
- [ ] 未完成事件的淡化展示（当前未区分）
- [ ] 用户手动补充完成项功能
- [ ] AI 总结可编辑/"换个说法"
- [ ] 分享卡片生成（隐私脱敏）
- [ ] 深夜时段的"明天再看"选项
- [ ] 特殊日期的定制化样式

## Today 模块关键设计原则（全局适用）

1. **信息折叠原则**：不要把全天计划细节摊开，避免心理负担。
2. **零摩擦原则**：3 秒知道今天怎么过，一键导航，长按快捷操作。
3. **温柔兜底原则**：空态、失败态、零完成态都要温暖，永远不说"你什么都没做""无结果"。
4. **Agent 而非 Chatbot**：AI 主动推荐、主动纠偏、主动兜底，不等用户问。
5. **等待即体验**：加载态要有温度，文案+动画，等待容忍度与情感价值成正比。
6. **情感曲线**：早上期待（阳光/可能）→ 白天陪伴+纠偏 → 晚上正反馈+收束。
7. **数据沉淀**：每次重新规划记录原因，每次推荐收集反馈，这是 AI 的护城河。
8. **隐私尊重**：分享自动脱敏，总结不暴露具体位置，敏感内容泛化表达。
